## 2. Routing e affidabilità
Comportamento ora verificato dal tool e dall'orchestratore con un planner scritto a mano (non dal modello reale):
| Dato | Risultato |
|---|---|
| `verified` | nessun `follow_up`, nessun passo esterno |
| `rule_based` | nota `identity_rule_based`, `reliability.identity = partial`, nessun `follow_up` (la risposta lo dichiara; il controllo è giudizio del planner) |
| `uncertain` | nota `identity_uncertain`, `reliability.identity = uncertain` **e un `follow_up` con motivo `data_gap:identity`** verso `tmdb_search` (verso `omdb_search` per `ratings`): **correzione di questa fase**, prima il tool dichiarava l'incertezza ma non offriva il passo. Un solo passo, il planner può chiudere con `done`; `provenance` non lo offre |
| assente / titolo ignoto | `empty`/`not_found` con UN `follow_up` verso lo strumento corrispondente (`ratings → omdb_search`, `awards → wikipedia_search`) |
| omonimi | `ambiguous`, nessun `follow_up` (sceglie l'utente) |
| dinamico (uscite, ultimi film) | regola 1g di base (`tmdb_search`); nessuno scenario del tool |
| cast | `billing_order` quando c'è, nessun passo esterno solo per sapere chi è in testa |
| persona fusa | compare una volta sola |
Nello stesso turno i passi esterni restano al più uno (verificato su 11 scenari in `tests/test_cinema_v3_routing.py`).
